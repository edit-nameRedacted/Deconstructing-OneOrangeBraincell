# Wan 2.2 in-betweens for the cat sheets — design

Nov 8, 2026 · from AC's handoff `temp/Animation Pipeline/Wan 2.2 First-Last-Frame Pipeline — Claude Code Handoff.md`,
adjusted after talking it through. Where this document and the handoff disagree, this document wins.

## Intent

AC draws keyframes with nano-banana and fixes them by hand (sheets like the grooming sheet and the full-body head
turn). The sheet tools in `SVG/sheet_tools/` already turn a sheet into layered SVGs (`r-<role>` groups for
recolouring, drawn eyes painted out and replaced by kit eyes placed from `cues.json`). What's missing is the
motion **between** the keyframes. This pipeline generates it with Wan 2.2 14B first-last-frame-to-video (FLF2V),
running locally in the existing ComfyUI container, and hands every generated frame to the same tracing steps, so
the D3 viz gets a short, choppy, quick animation whose eyes and colours it can still swap programmatically.

## Goals

- From a sheet (or a list of keyframe PNGs) produce one continuous sequence: keyframe 1 → 2 → … → n, each step
  generated by Wan, joined into one numbered PNG sequence, then traced into one layered SVG per frame.
- Default timing: **12 fps, 0.5 s per step**, both adjustable; each step can have its own duration and motion
  prompt. Motion should read as quick; choppy is fine.
- AC's hand-edited keyframes appear **unchanged** at the joins (the generated endpoint frames are replaced by the
  originals; the runner reports how far the generated ones were off).
- Output SVGs match what the sheet tools make today: same roles and classes, `cues.json` with eye and nose
  positions for **every** frame, kit eyes placeable with `place_eyes.py`. No background (the trace already drops
  the paper; that is the "transparent background").
- Runs on the RTX 4070 SUPER (12 GB) inside the Docker VM's current ~31 GB RAM limit.
- Reproducible: same keyframes, prompts and seed give the same frames, and everything runs from the command line.

## Non-goals

- Frame rates above 16 fps. Wan generates at 16 fps; at ≤16 fps the runner picks the nearest generated frame, so
  **RIFE and the Frame-Interpolation node pack are dropped** (handoff said to use them). Add them back only if a
  rate above 16 fps is ever needed.
- VideoHelperSuite / MP4 previews (the GIF preview below covers it).
- 720p, Q5_K_M experts, the 5B fallback — only if the default fails or AC asks.
- Fixing per-frame trace wobble ("line boil") or eye flicker in this round. They are measured and shown, not
  solved (see Risks).
- Blinks. AC's rule: **a blink and a head turn never happen in the same step.** Blinks are a separate keyframe
  pair with the head held still (or done by the viz swapping eyes).

## Anti-goals (would make it a failure even if it runs)

- Keyframes come out altered (cropped, stretched, recoloured) at the joins.
- The cat changes style mid-step: shading, texture, softened or thickened outlines that the colour roles can't
  absorb.
- Kit eyes that slide off the face because eye positions were guessed rather than read from each frame.
- Anything that only works by hand-editing outputs. Every fix lives in code or the workflow (AC's standing rule).

## Decisions made

**By AC in the conversation**
- Input: keyframe sheets in a grid, as made with nano-banana and edited by hand. Test subjects: the grooming sheet
  `sheets/grooming_sheet.jpg` (2000×1500, ~240×450 px per cat; the sheet tools already find all 12 frames and
  their eyes) and the full-body head-turn sheet (5 poses on grid paper). The head-turn copies so far are too
  small (921×442 PNG and 1024×765 WebP, both ~180×360 px per cat: the tools find 4 cats and no eyes).
  *Claude's call:* the grooming sheet goes first; the head turn follows once a full-size file is available. No
  upscaling, since that would alter the keyframes.
- Output: individual frames → layered SVG, eyes and colours swappable by the viz.
- Eyes stay drawn through Wan and are removed afterwards, per frame, by the existing cue → paint-out step (keyframes
  with their eyes removed would make Wan regrow eyes, and the in-between eye positions would have to be guessed).
- No blink and head turn in the same step.
- Start within the Docker VM's 32 GB; raise the WSL memory limit only if it runs out, and ask first.

**Kept from the handoff**
- Wan 2.2 I2V A14B, Q4_K_M GGUF high- and low-noise experts via ComfyUI-GGUF (`UnetLoaderGGUF`), Lightning 4-step
  LoRA pair at 1.0, `wan_2.1_vae`, `umt5_xxl_fp8_e4m3fn_scaled` text encoder in `CLIPLoader` type `wan`.
- Sampler settings: 4 steps split 2/2, CFG 1, shift 5, euler/simple, same fixed seed on both `KSamplerAdvanced`
  nodes, add-noise/leftover-noise as in the handoff's table. Start from the template
  `video_wan2_2_14B_flf2v.json` (present in the container's `comfyui_workflow_templates_media_video` package);
  `WanFirstLastFrameToVideo` is in core ComfyUI 0.8.2.
- Frame length L = 4·round(16·S/4)+1, capped at 81 with a warning; D = (L−1)/16 is reported.
- Negative prompt does nothing at CFG 1; say so, don't advertise it.
- One UI workflow plus its API-format twin; the runner talks to ComfyUI over HTTP (`/upload/image`, `/prompt`,
  `/history/<id>`, `/view`) with the standard library and Pillow.
- Repeatability check: same seed twice, report the largest per-pixel difference if not identical.
- Ask before: going above 480p, switching to Q5_K_M, driver/CUDA updates, installing outside the ComfyUI and
  project folders.

**Claude's calls (AC can override)**
- **Frame picking without RIFE.** Output frame j (j = 0 … N−1, N = round(D·F)+1) is generated frame
  round(16·j/F). Error is at most 1/32 s. F > 16 is refused with a message that RIFE is needed. Tests, in place of
  the handoff's table: 3 s @ 16 → L 49, N 49, every frame; 5 s @ 12 → L 81, N 61; 0.5 s @ 12 → L 9, N 7
  (picks 0,1,3,4,5,7,8); 0.5 s @ 8 → L 9, N 5 (every 2nd); 2.1 s @ 8 → L 33, D 2.0, N 17; 6 s → capped at 81 with
  a warning.
- **Chaining.** A sequence of n keyframes is n−1 independent Wan runs. Segment k's first output frame is dropped
  when k > 1 (it is the previous segment's last). Total frames = 1 + Σ(N_k − 1). Exact endpoints are **on by
  default** for sequences.
- **Working size: pad, never crop.** The aligned canvas (`sheet_frames.py` output, e.g. 419×599 or 605×661) is
  scaled uniformly to about 400k pixels (the handoff's 832×480 budget), padded with white to multiples of 16, sent
  to Wan, and the transform undone on the way back so every output frame is on the original canvas and lines up
  with the keyframes' cues.
- **Prompting.** Each step has a short motion prompt ("lifts its right front paw to its mouth"), and every prompt
  gets the same style tail appended (flat-colour 2D cartoon, clean dark brown outlines, plain white background,
  static camera, no shading). The exact wording is tuned during the first test.
- **Blink guard.** The runner reads each step's two keyframes' eye state from `cues.json` and warns when one has
  eyes open and the other closed, naming the rule.
- **Where things go.**
  - ComfyUI side: **a pipeline of its own, independent of the bust pipeline** (AC's requirement: neither project
    touches the other). New folder `C:\Users\Watcher\Documents\pysandbox\comfyui_wan\` with its own
    `Dockerfile`, `docker-compose.yml`, `models/{unet,loras,vae,text_encoders}/`, `input/`, `output/` and
    `workflows/` (UI workflow `wan22_flf2v_12gb.json`). Image `comfyui-wan:local`, container `comfyui-wan`,
    port **8189**. The Dockerfile starts from the same pinned base as the bust image
    (`ghcr.io/lecode-official/comfyui-docker:0.6.3-comfyui-0.8.2-comfyui-manager-4.0.5-pytorch-2.9.1-cuda-12.6-cudnn-9`)
    and adds only ComfyUI-GGUF, pinned to a commit, by git clone + pip (ComfyUI-Manager installs fail silently
    in that base). No CUDA toolkit, no 3D-Pack, no shared volumes, no restart policy (started on demand).
  - The bust pipeline (`temp/comfyui3d/`, image `comfyui-3d:local`, container `comfyui-3d`) is **not edited,
    rebuilt, re-tagged or given any files**. The only interaction: both need the one GPU and the ~31 GB Docker
    VM, so the bust container is stopped (`docker stop comfyui-3d`) while Wan runs and started again afterwards
    (`docker start comfyui-3d`), which changes nothing in it. Claude asks before stopping it; the README tells AC
    to run one at a time.
  - Project side (`Orange_Braincells/SVG/sheet_tools/`): `flf_runner.py` (runner, frame math in one small
    function), `test_frame_math.py` (no GPU), `wan22_flf2v_12gb_api.json`, a sequence file per animation, and a
    frames-folder entry into the existing tracing. Runs land in `out/<name>/`. README section added to
    `sheet_tools/README.md`, not a new README.
- **Sequence file** (one per animation, JSON): keyframe source (a sheet, traced with `sheet_frames.py` first, or a
  list of PNGs on one canvas), fps, default seconds, seed, the **order as a list of keyframe numbers** (any order,
  repeats allowed, e.g. the head turn's ping-pong 3,2,1,2,3,4,5,4,3), an optional `loop` flag, the front frame for
  `place_eyes.py --front`, and per step an optional prompt and seconds. A step that is the reverse of one already
  generated (2→1 after 1→2) reuses those frames reversed instead of a new Wan run. With `loop`, the order ends on
  its first keyframe and that last frame is dropped so the loop doesn't stutter. The runner also accepts a single
  `--start/--end` pair as in the handoff.
- **Grooming order** is the sheet's reading order (12 frames), ignoring the printed labels. Its steps 7→8 and
  9→10 change eye state while the paw moves; for the test they run with the blink warning, and the result shows
  whether hold keyframes are needed.
- **Durability of the Wan image.** After it works, its `pip freeze` is saved as `comfyui_wan/requirements.lock`
  and used as a constraint file in the Dockerfile, so a later rebuild gets the same versions (the lesson from
  the bust image, whose unpinned builds drifted).
- **Frames into SVG.** Reuse `sheet_frames.py`'s per-frame steps (cue reading, eye paint-out, `trace_layers`) on
  a folder of already-registered frames, **without** its base-anchor re-alignment (that would make the cat jitter
  as paws move). Refactor the per-frame body into a function both paths call rather than copying it. Writes
  `frame_NNNNN.svg` and one `cues.json` for the whole sequence; `place_eyes.py` and the preview scripts must
  accept it (check their filename patterns).
- **Run record.** `run.json` per run: all arguments, seed, per-step L/D/N, model file names, ComfyUI version,
  times, peak VRAM, peak container RAM, generated-vs-original endpoint mean difference, and per-frame eye
  detection (open / closed / missing).
- **Preview for AC.** An animated GIF of the traced frames with kit eyes, played at the chosen fps (reusing
  `render_turn.py`'s Playwright rendering), plus a contact sheet — so AC can judge boil and eye flicker in one
  look.

## Container traps (learned building the bust image; the Wan Dockerfile must avoid each)

Sources: `temp/comfyui3d/Dockerfile`, `startup.sh`, `comfyui3d_env.pth`, the base image's `/entrypoint.sh`, and
the bust-pipeline memory notes.

1. **Unpinned builds drift.** Pin the base image tag (above), the ComfyUI-GGUF commit, and install its
   requirements with a constraint file. Fresh `pip` resolves picked e.g. huggingface_hub 1.x and broke the bust
   image.
2. **The base entrypoint re-runs `pip install -r requirements.txt` for every custom node on every start**,
   unconstrained, as root. Set `ENV PIP_CONSTRAINT=<lock file>` in the image so those start-up installs can't
   move versions either.
3. **ComfyUI-Manager 4.x installs fail silently** in this base. Install nodes by git clone + pip in the
   Dockerfile. The Wan image doesn't need Manager at all: no `--enable-manager`, no `startup.sh`, use the base
   entrypoint as is.
4. **`sudo` drops environment variables.** With `USER_ID/GROUP_ID` set, the entrypoint runs ComfyUI via
   `sudo --preserve-env=PATH`, so `environment:` entries and Dockerfile `ENV`s don't reach ComfyUI. Anything
   ComfyUI itself needs (cache dirs) goes in a `.pth` start-up line like `comfyui3d_env.pth`. Probably not needed
   here (no runtime downloads), but if a library wants a writable cache, this is the fix.
5. **Never mount anything under `/home/comfyui-user`.** Root-owned parent dirs make startup fail on restart
   (uv can't create `~/.cache/uv`). Mount only under `/opt/comfyui/…`.
6. **The entrypoint `chown -R`s `/opt/comfyui` on every start**, mounts included. Fine for model files, but
   nothing that must stay root-owned goes there.
7. **The entrypoint hard-codes `--port 8188`.** Map host 8189 → container 8188 in compose; don't try to change
   ComfyUI's port.
8. **Run as the host user** (`USER_ID=1000`, `GROUP_ID=1000`), like the bust container, so outputs on the host
   mounts aren't root-owned.
9. **GPU in compose**: `deploy.resources.reservations.devices` with the `nvidia` driver, as in the bust
   compose file. No CUDA toolkit or `TORCH_CUDA_ARCH_LIST` needed: ComfyUI-GGUF compiles nothing.
10. **Keep weights out of the build context** with a `.dockerignore` (`/models`, `/output`, `/input`), or every
    build copies ~29 GB.
11. **Restart policies fight over the GPU.** The bust container is `restart: unless-stopped`; the Wan container
    gets no restart policy, so Docker never starts both. After `docker stop comfyui-3d` the bust container stays
    stopped until `docker start comfyui-3d`, even across a reboot — the README and the final report must say so.
12. **Names.** Don't reuse `comfyui-3d`, `comfyui-3d:local`, or the old exited container `comfyui` (July,
    unrelated, leave alone).
13. **Rebuilds are slow and deliberate.** Order Dockerfile layers so the node-pack layer is last and cached base
    layers are reused; never run `docker compose up --build` casually.
14. **Model loading from a Windows bind mount may be slow** (19 GB of experts read through the WSL file share,
    possibly on every run if the 31 GB VM can't keep both cached). Measure load time in the smoke test; if it
    dominates, propose a named Docker volume for `models/` and ask AC before switching.
15. **`hf download --local-dir` keeps the repo's subfolders** (`HighNoise/…`, `split_files/…`); move each file
    to its ComfyUI folder flat, and make sure they are real files, not symlinks into a cache.

## Build order and checks

1. **Machine check.** Already known: 12 GB RTX 4070 SUPER (about 8 GB of it held by the idle bust container),
   Docker VM ~31 GB RAM, C: 431 GB free. Re-confirm and record.
2. **Build the Wan container** in `comfyui_wan/` and download the six model files (~29 GB) with `hf download`
   into its `models/…`. *Downloading needs AC's go-ahead (approving this document counts).* Check: with the bust
   container stopped, `comfyui-wan` starts with no import errors, the UI workflow loads with no red nodes, and
   `docker start comfyui-3d` afterwards brings the bust container back unchanged.
3. **Smoke test** on the grooming sheet, keyframes 1→2 at 0.5 s, then 2→3 at 1 s. Record time, peak VRAM, peak
   container RAM. If the container runs out of memory: first ComfyUI memory flags (e.g. not caching models
   between runs), then 640×368-equivalent size, then Q3_K_M — and if still failing, stop and ask about raising
   the WSL limit. Check: a clip that starts and ends on the two keyframes and stays on-model.
4. **Frame math tests** pass before the runner is written.
5. **Runner**, single pair: counts match for the test cases above; repeat run with the same seed.
6. **Sequence**: the whole grooming sheet (11 steps), joins equal the keyframes exactly.
7. **Frames into SVG** + kit eyes + GIF preview. Report eye-detection per frame and flag isolated flips.
8. **Head-turn sheet** (ping-pong, looped) once a full-size file exists; otherwise left for later.
9. README section, then a short report to AC: what ran, times, memory, what deviated from this document, and the
   preview GIFs for AC to judge.

## Risks to watch (measured, not solved, this round)

- **Style drift**: Wan is trained on real video and may add shading or soften lines. First thing to check in the
  smoke test.
- **Eye detection on generated frames**: soft eye whites may fall outside `eyes_and_nose`' thresholds, so the
  kit eyes flicker. Reported per frame.
- **Line boil**: each frame traced on its own. Visible in the GIF.
- **Colour roles**: VAE colour shift pushing pixels into the wrong role.
- **Memory**: 19.4 GB of experts + 6.7 GB text encoder in a ~31 GB VM shared with the small always-on
  containers (~1 GB together; the bust container is stopped during Wan runs).
- **Short steps**: at 0.5 s Wan gets only 9 frames (3 latent frames); big pose changes may cross-fade instead of
  move. If so, lengthen those steps or add a keyframe.
